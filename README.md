# PdfUtil

A PDF helper library for .NET 8. It can:

1. **Protect.** It encrypts a PDF with a user password, an owner password, or both, plus permission flags.
2. **Verify passwords.** It reports whether a password opens a PDF and whether it matched as the *user* or the *owner* password.
3. **Inspect.** It returns version, page, encryption, Info, XMP and `/ID` details as a strongly typed model, and on request the fonts, images, attachments, bookmarks, form fields, signatures, page labels and actions.
4. **Edit.** It removes or changes protection and changes document information.
5. **Validate and repair.** It reports every structural problem with a code and object number, and writes a clean, single-revision copy of a damaged file.
6. **Sanitize.** It removes JavaScript, actions, attachments, annotations and metadata.
7. **Manage attachments.** It adds, removes, lists and extracts embedded files.
8. **Work with pages.** It rotates, deletes, merges and splits pages.
9. **Extract text and stamp.** It extracts text with positions, fonts and colours, and adds text or image watermarks.
10. **Sign and encrypt for certificates** (PdfUtil.Signatures). It signs (PAdES, with timestamps), verifies signatures, and encrypts for recipients' certificates.
11. **Convert** (PdfUtil.Conversion). It converts PDFs to reflowable or fixed-layout HTML and to Word, and HTML and Word to PDF.
12. **Command line** (PdfUtil.Cli). Every feature is available as a `pdfutil` command.

Everything works for PDF 1.0 through 2.0, and every file PdfUtil writes is verified before you get it.

## Usage

### Static facade (synchronous)

```csharp
using PdfUtil;

var result = Pdf.Protect("in.pdf", "out.pdf", new PdfProtectionOptions
{
    UserPassword = "open-sesame",
    OwnerPassword = "full-access",
    Permissions = PdfPermissions.Print | PdfPermissions.ExtractForAccessibility,
    Algorithm = PdfEncryptionAlgorithm.Aes256,   // default
});
Console.WriteLine($"PDF {result.SourceVersion} -> {result.OutputVersion}");
foreach (var w in result.Warnings) Console.WriteLine(w);

var check = Pdf.VerifyPassword("out.pdf", "open-sesame");  // IsValid = true, MatchedAs = User
var info  = Pdf.GetInfo("out.pdf", "full-access");          // pages, Info, XMP, /ID, encryption...
byte[] protectedBytes = Pdf.Protect(File.ReadAllBytes("in.pdf"), options);
```

### Services (async, cancellable)

```csharp
IPdfProtector protector = new PdfProtector(new PdfUtilOptions { MaxFileSizeBytes = 500_000_000 });
await using var input = File.OpenRead("in.pdf");
await using var output = File.Create("out.pdf");
PdfProtectionResult r = await protector.ProtectAsync(input, output, options, cancellationToken);

IPdfOpener opener = new PdfOpener();
PdfPasswordCheckResult c = await opener.VerifyPasswordAsync(stream, "pw");   // never throws for a wrong password
bool encrypted = await opener.IsEncryptedAsync(stream);

IPdfInspector inspector = new PdfInspector();
PdfDocumentInfo d = await inspector.GetInfoAsync(stream, password: null);
```

`ProtectFileAsync` writes to a temporary file next to the destination, verifies it, and then replaces the destination atomically. A failed protection never leaves a partial file, and the input and output paths may be the same. `ProtectAsync` writes nothing to `output` until the protected document has passed verification.

### Dependency injection

```csharp
services.AddLogging();
services.AddPdfUtil(o => o.MaxDecompressedStreamBytes = 64 * 1024 * 1024);
// inject IPdfProtector, IPdfEditor, IPdfOpener, IPdfInspector, IPdfAnalyzer, IPdfCleaner,
// IPdfAttachmentManager, IPdfPageEditor, IPdfTextExtractor, IPdfStamper, IPdfBatchProcessor
// and IPdfPipelineFactory (singletons)
```

When an `ILoggerFactory` is registered, the library's log callback is bridged to an `ILogger` with category `PdfUtil`. Log messages never contain passwords, keys or document content.

### Chaining operations (PdfPipeline)

`PdfPipeline` runs several operations on one document, each step reading the previous step's output. Nothing runs until a terminal method (`ToBytesAsync`, `ToStreamAsync`, `SaveAsync` or `RunAsync`) is called.

```csharp
byte[] pdf = await PdfPipeline.FromFile("report.pdf")
    .Watermark("CONFIDENTIAL")
    .RotatePages(90, "1-2")
    .EditInfo(i => i.Title = "Q3 report")
    .Protect(userPassword: "open-me", ownerPassword: "owner")
    .ToBytesAsync();

// Or save atomically and look at what each step did.
var result = await PdfPipeline.FromBytes(pdf)
    .WithPassword("owner")                 // opens the protected input
    .AddAttachment("data.csv", csvBytes)
    .Decrypt()
    .SaveAsync("report-final.pdf");
foreach (var step in result.Steps)
    Console.WriteLine($"{step.Name}: {step.Result}");
```

* **Sources:** `FromFile`, `FromBytes`, `FromStream`, each with optional `PdfUtilOptions`. With DI, inject `IPdfPipelineFactory`, which uses the application's options.
* **Steps:** `Stamp` / `Watermark`, `Protect`, `Decrypt`, `ChangeSecurity`, `EditInfo`, `RotatePages`, `DeletePages`, `Append` (merge other documents after this one), `Repair`, `Sanitize`, `AddAttachment`, `RemoveAttachment`, and `Then(name, step)` for your own step. `PdfUtil.Signatures` adds `.Sign(options)`; make it the last step, because any later change invalidates the signature, and it cannot follow `Protect`.
* **Passwords carry forward:** `WithPassword` opens the input. After `Protect` or `ChangeSecurity`, later steps open the result with the new owner password, and after `Decrypt` they need none. A password set on a step's own options wins. Your options objects are left unchanged.
* **Order matters:** put `Protect` at the end, so the earlier steps don't each decrypt and re-encrypt the document. `Append` returns an unprotected document.
* **Safety:** every step keeps its own self-verification. If a step fails, its exception propagates with its original type, `ex.Data["PdfPipelineStep"]` names the step (for example `"2: DeletePages"`), and nothing is written. `SaveAsync` replaces the file atomically, so the input file can also be the output.
* Intermediate documents are kept in memory. A pipeline can run more than once; each run reads the input again.

## Supported input

* PDF 1.0–1.7 and 2.0, with junk tolerated before `%PDF-` in the first 1024 bytes.
* Classic xref tables (19/20/21-byte entries, multiple subsections), xref streams (PNG predictors 10–15, TIFF predictor 2), object streams (`/Extends`), and hybrid files (`/XRefStm`).
* Incremental updates (`/Prev` chains; the last trailer wins; loops are detected).
* Linearized files, and PDF/A, PDF/X and PDF/UA files.
* Damaged files. Wrong offsets or a broken xref are rebuilt by scanning for `n g obj`, and a wrong `/Length` is resolved by locating `endstream`.
* Encrypted files of every Standard Security Handler revision: R2 (RC4-40), R3 (RC4-128), R4 (RC4 or AES-128 crypt filters, `/StmF` `/StrF` `/EFF`, `/Identity`), R5 (deprecated AES-256) and R6 (AES-256).
* Public-key (`/Adobe.PubSec`) and unknown handlers throw `PdfUnsupportedEncryptionException`.

Only FlateDecode is ever decoded, and only where needed (xref streams, object streams, XMP). Every other filter is passed through untouched. Page content and fonts are treated as opaque.

## Output format

The output is a full rewrite for maximum compatibility:

* the header `%PDF-x.y`, followed by a binary comment line;
* plain indirect objects only, with no object streams and no xref stream;
* one classic xref table with exactly 20-byte entries, then `trailer` (`/Size /Root /Info /ID /Encrypt`), `startxref` and `%%EOF`.

This is the default. `PdfWriteOptions.UseObjectStreams` gives smaller files, and `PdfSaveMode.Incremental` appends changes instead of rewriting; see [Smaller files and incremental saves](#smaller-files-and-incremental-saves).

Original object numbers are kept. Stream data is decrypted (if needed) and re-encrypted byte-exact, never re-compressed, and each `/Length` is updated to the encrypted length. Objects not reachable from the catalog or Info dictionary are dropped: the linearization dictionary, hint streams, old xref streams and object-stream containers. The output therefore never claims to be linearized.

### Algorithms and reader compatibility

| `Algorithm` | Handler | `/Encrypt` written | Output version | Reader support |
|---|---|---|---|---|
| `Aes256` (default) | V5 / R6 | `/V 5 /R 6 /Length 256`, `/CF <</StdCF <</CFM /AESV3 /AuthEvent /DocOpen /Length 32>>>>`, `/StmF /StrF /StdCF`, 48-byte `/O` `/U`, 32-byte `/OE` `/UE`, 16-byte `/Perms`, `/P` | max(source, 1.7) plus `/Extensions <</ADBE <</BaseVersion /1.7 /ExtensionLevel 8>>>>`, or 2.0 if the source is 2.0 | All current browsers (Chrome/Edge PDFium, Firefox pdf.js, Safari PDFKit), Acrobat/Reader X+, Foxit, SumatraPDF, macOS Preview, iOS/Android, qpdf, mutool |
| `Aes128` | V4 / R4 | `/V 4 /R 4 /Length 128`, `/CF <</StdCF <</CFM /AESV2 /AuthEvent /DocOpen /Length 16>>>>` | max(source, 1.6) | Additionally Acrobat 7–9 era readers (~2005+) |
| `Rc4_128` | V2 / R3 | `/V 2 /R 3 /Length 128` | max(source, 1.4) | Practically every reader, including very old ones. RC4 is cryptographically weak, so use it only for legacy needs. |

R5 is never written. The version is never lowered, and a catalog `/Version` entry is kept equal to the header. `/EncryptMetadata` is omitted (default `true`) unless `EncryptMetadata = false` is requested, which is valid for AES only. `/O /U /OE /UE /Perms` are hex strings. `/P` is a signed 32-bit value with reserved bits 7–8 and 13–32 set, and the same value is used in key derivation.

**Readers from before roughly 2008 (for example Acrobat 8 and earlier) cannot open AES-256 files. Use `Algorithm = Aes128` for them, or `Rc4_128` for the very oldest.**

### Changing document information

`InfoChanges` updates the document information while protecting. Properties left `null` keep their current value. If the document has XMP metadata, the matching XMP properties are updated too, so every viewer shows the same values.

```csharp
var options = new PdfProtectionOptions
{
    UserPassword = "open-sesame",
    OwnerPassword = "full-access",
    InfoChanges = new PdfInfoChanges
    {
        Title = "Quarterly report",
        Author = "Finance team",
        UpdateModificationDate = true,
    },
};
options.InfoChanges.CustomProperties["Department"] = "Finance";
options.InfoChanges.Remove.Add("Keywords");
```

| `PdfInfoChanges` member | Info entry | XMP property |
|---|---|---|
| `Title` | `/Title` | `dc:title` |
| `Author` | `/Author` | `dc:creator` |
| `Subject` | `/Subject` | `dc:description` |
| `Keywords` | `/Keywords` | `pdf:Keywords` |
| `Creator` | `/Creator` | `xmp:CreatorTool` |
| `Producer` | `/Producer` | `pdf:Producer` |
| `CreationDate` | `/CreationDate` | `xmp:CreateDate` |
| `ModificationDate`, or `UpdateModificationDate = true` for now | `/ModDate` | `xmp:ModifyDate` |
| `CustomProperties[key]` | `/key` | (Info only) |
| `Remove.Add(key)` | removes `/key` | removes the matching property |

* Text is written in PDFDocEncoding when possible, otherwise as UTF-16BE, so any language works in every PDF version.
* A document without an Info dictionary gets one.
* Custom keys must be printable ASCII without spaces, and can't be standard keys.
* `result.DocumentInfoChanged` and `result.XmpUpdated` report what happened. If the XMP can't be parsed, it is left untouched and a warning is added.
* Self-verification checks that the output's Info dictionary and XMP contain exactly the requested values.

### Removing and changing protection

`IPdfEditor` (or the `Pdf` facade) edits documents that are already protected. Every edit goes through the same self-verification as protection, and file output is replaced atomically.

```csharp
// Remove protection. Requires the owner password; the password to open is refused unless AllowUserPassword is set.
Pdf.Decrypt("report-protected.pdf", "report-unlocked.pdf", "owner-password");

// Change passwords, permissions or algorithm. Anything left null keeps its current value.
Pdf.ChangeSecurity("report-protected.pdf", "report-new-password.pdf", new PdfSecurityChanges
{
    CurrentOwnerPassword = "owner-password",
    UserPassword = "new-password",
    Permissions = PdfPermissions.Print,
});

// Change document information and keep the protection exactly as it is.
Pdf.EditInfo("report-protected.pdf", "report-renamed.pdf", new PdfInfoChanges { Title = "Q3 report (final)" }, "owner-password");
```

| Operation | Needs | Output security |
|---|---|---|
| `DecryptAsync` | Owner password (or the open password with `AllowUserPassword`) | None |
| `ChangeSecurityAsync` | Owner password | New settings; unspecified ones are kept |
| `EditInfoAsync` | Owner password for protected files; nothing for unprotected ones | Unchanged: the same `/Encrypt` dictionary and file key, so every password and permission stays the same |

What "keep" means in `ChangeSecurityAsync`:
* **Owner password:** kept as `CurrentOwnerPassword`.
* **Permissions, algorithm, metadata encryption:** kept as they are. RC4 40-bit and AES-256 revision 5 are upgraded to RC4 128-bit and AES-256 revision 6, with a warning.
* **Password to open:** for RC4 and AES-128 files, it is recovered from the owner password and kept byte for byte. For AES-256 files it can't be recovered, so it can only be kept when it is empty; otherwise set `UserPassword`.

`EditInfoAsync` refuses files encrypted with RC4 40-bit or AES-256 revision 5, which PdfUtil does not write; use `ChangeSecurityAsync` for those. `ChangeSecurityAsync` on an unprotected file throws `PdfNotEncryptedException`.

### Batch processing

`IPdfBatchProcessor` runs any operation over many documents in parallel. A failing file never stops the batch unless `StopOnFirstError` is set; results come back in input order with status, error, warnings and duration.

```csharp
IPdfBatchProcessor batch = new PdfBatchProcessor();
var jobs = Directory.GetFiles("in", "*.pdf").Select(f => new PdfFileJob(f, Path.Combine("out", Path.GetFileName(f))));
var results = await batch.ProtectFilesAsync(jobs, options, new PdfBatchOptions { MaxDegreeOfParallelism = 4 });
Console.WriteLine($"{results.Succeeded} succeeded, {results.Failed} failed");
```

There are helpers for protect, decrypt, inspect and verify, and `RunAsync` for any other operation. `PdfBatchOptions.Progress` reports after each item.

### Progress

Every operation that writes a PDF accepts an `IProgress<PdfProgress>` through its options (`Progress` property). Reports cover three stages: Reading, Writing and Verifying. They arrive at most about every 100 ms, and the first and last report of each stage are always delivered.

```csharp
options.Progress = new Progress<PdfProgress>(p => Console.WriteLine($"{p.Stage}: {p.Fraction:P0}"));
```

### PDF/A, signatures and existing encryption

* **PDF/A forbids encryption.** PdfUtil detects PDF/A from the XMP `pdfaid` entries. The default `PdfAPolicy.Throw` throws `PdfComplianceException`. `PdfAPolicy.Proceed` encrypts anyway and adds a warning.
* **Signed input:** protection rewrites the file and invalidates existing signatures, so a warning is added. Signature `/Contents` strings are never encrypted.
* **Already-encrypted input:** the default `AlreadyEncryptedPolicy.Throw` throws `PdfAlreadyEncryptedException`. `ReEncryptWithOwnerPassword` together with `CurrentOwnerPassword` decrypts the file and re-encrypts it. The password must authenticate as the owner password; the user password is not enough.

### Inspecting details

`Pdf.Inspect` (or `IPdfAnalyzer.InspectAsync`) returns everything `GetInfo` returns, plus the details you select. The default is all of them; select fewer to keep inspection fast on large files.

```csharp
var info = Pdf.Inspect("report.pdf");                       // every detail
foreach (var font in info.Fonts)
{
    Console.WriteLine($"{font.Name} ({font.Subtype}), embedded: {font.IsEmbedded}, pages {string.Join(", ", font.Pages)}");
}

foreach (var bookmark in info.Bookmarks)
{
    Console.WriteLine($"{bookmark.Title} -> page {bookmark.Page}");
}

var fontsOnly = Pdf.Inspect("report.pdf", new PdfInspectionOptions { Details = PdfInspectionDetails.Fonts });
```

| Detail | What is reported |
|---|---|
| `Fonts` | Name (without subset prefix), type (Type1, TrueType, Type0 with its CID font type, Type3), embedded or not, subset, font file type, encoding, `/ToUnicode`, pages. Fonts in form XObjects, Type 3 resources and annotation appearances are included |
| `Images` | Pages, pixel size, bits per component, colour space (for example `ICCBased (3 components)` or `Indexed (DeviceRGB, 256 colours)`), filters, soft mask, stored size |
| `Attachments` | Name, file name, description, size, MIME type, dates, MD5 checksum, `/AFRelationship`, and the page for file attachment annotations. `/Kids` name trees are followed |
| `Bookmarks` | The outline tree with decoded titles; destinations (explicit, named, or GoTo actions) resolved to page numbers; other actions by type, with the target of URI actions |
| `FormFields` | Fully qualified name, type (text, check box, radio button, push button, combo box, list box, signature), value, flags, tooltip, pages |
| `Signatures` | Field name, signer name, signing time, reason, location, filter and `/SubFilter`, byte range, and whether the byte range covers the whole file except the signature value. Signatures are not validated cryptographically |
| `PageLabels` | The label of every page (`i`, `ii`, `A-5`, ...) |
| `Actions` | Whether there is JavaScript, the names of document scripts (never their source), and every action with its location and type |

`PageLayout`, `PageMode` and `Language` are always filled in, also by `GetInfo`.

### Validation

`Pdf.Validate` (or `IPdfAnalyzer.ValidateAsync`) reads the file with the recovery reader and returns a report instead of throwing. Each issue has a severity (`Info`, `Warning`, `Error`), a stable code from `PdfValidationCodes`, a message and the object number.

```csharp
var report = Pdf.Validate("damaged.pdf");
Console.WriteLine(report.IsValid ? "No errors" : $"{report.Errors.Count()} error(s)");
foreach (var issue in report.Issues)
{
    Console.WriteLine(issue);   // e.g. "Error XrefReconstructed: The cross-reference information was damaged..."
}
```

It checks the cross-reference data (rebuilt, wrong offsets, `/Prev` loops, `/Size`), every object (unreadable, missing, wrong stream `/Length`, references to objects that don't exist), dates (`/CreationDate`, `/ModDate`, and `/M` of annotations and signatures), the page tree (`/Count`, `/Parent`, `/Type`, cycles, missing `/MediaBox`), the encryption dictionary (`/R` and `/V`, string lengths, crypt filters, a missing `/ID`), FlateDecode streams (undecodable, truncated, wrong checksum) and the XMP packet. A file that cannot be read at all gives a report with `IsReadable = false`. For an encrypted file, pass a password to check its objects and streams; without one only the structure is checked. `CheckStreams = false` skips decompression for a faster check.

### Repair

`Pdf.Repair` (or `IPdfCleaner.RepairAsync`) writes a clean, single-revision copy through the recovery reader, and lists exactly what it repaired.

```csharp
var repair = Pdf.Repair("damaged.pdf", "repaired.pdf");
foreach (var line in repair.Repairs)
{
    Console.WriteLine(line);   // e.g. "Rebuilt the damaged cross-reference information by scanning the file."
}

if (repair.PagesMayBeMissing)
{
    Console.WriteLine($"Only {repair.PageCount} of {repair.DeclaredPageCount} pages could be recovered.");
}
```

Repairs include: rebuilt cross-reference data, corrected offsets and stream lengths, junk before the header, page tree fixes (`/Count`, `/Parent`, repeated or invalid `/Kids` entries, a default `/MediaBox`), and references to missing objects. The copy is also normalized: incremental updates merged, object and cross-reference streams rewritten as a classic table, linearization removed, unused objects dropped. Pages are never dropped silently: if the page tree declares more pages than can be read, or page objects sit outside the page tree, `PagesMayBeMissing` is set and a warning says how many. Protected files keep exactly the same security (this needs the owner password), unless `RemoveProtection` is set.

### Sanitize

`Pdf.Sanitize` (or `IPdfCleaner.SanitizeAsync`) removes what you select and lists every item it removed.

```csharp
var sanitize = Pdf.Sanitize("report.pdf", "clean.pdf", new PdfSanitizeOptions
{
    RemoveJavaScript = true,        // on by default
    RemoveAttachments = true,
    RemoveDocumentInfo = true,
});
foreach (var item in sanitize.Removed)
{
    Console.WriteLine($"{item.Kind}: {item.Description}");   // e.g. "JavaScript: Document script \"init\""
}
```

| Option | Removes |
|---|---|
| `RemoveJavaScript` (default on) | Document scripts and JavaScript actions of the document, pages, annotations, form fields and bookmarks, including those in `/Next` chains. Other actions stay |
| `RemoveActions` | The open action and every `/AA` dictionary, whatever the action type |
| `RemoveAttachments` | The `/EmbeddedFiles` tree, file attachment annotations, associated files (`/AF`) and portfolios |
| `RemoveAnnotations` | Annotations (links are kept unless `KeepLinks = false`) and the interactive form |
| `RemoveDocumentInfo` | The Info dictionary |
| `RemoveXmp` | XMP metadata of the document, pages, images and other objects. PDF/A input gets a warning, because PDF/A requires XMP |

`PdfSanitizeOptions.All()` switches everything on. Protected files keep exactly the same security (this needs the owner password).

### Attachments

`IPdfAttachmentManager` (or the `Pdf` facade) works with document-level attachments.

```csharp
Pdf.AddAttachment("report.pdf", "report-with-data.pdf", new PdfAddAttachmentOptions
{
    Name = "data.xml",
    Content = File.ReadAllBytes("data.xml"),
    MimeType = "application/xml",
    Description = "Source data",
    Relationship = PdfAttachmentRelationship.Data,   // also lists it in /AF, as PDF/A-3 requires
});

foreach (var attachment in Pdf.ListAttachments("report-with-data.pdf"))
{
    Console.WriteLine($"{attachment.Name}: {attachment.Size} bytes, {attachment.MimeType}");
}

byte[] xml = Pdf.ExtractAttachment("report-with-data.pdf", "data.xml");
Pdf.RemoveAttachment("report-with-data.pdf", "report-without-data.pdf", "data.xml");
```

* Each attachment gets a file specification with `/F` and `/UF` (so any file name works), `/Params` (size, creation and modification dates, MD5 checksum), `/Subtype` with the MIME type, and an optional `/AFRelationship`.
* The `/EmbeddedFiles` name tree is rewritten as one sorted node; existing `/Kids` trees are read in full first.
* An existing name throws `ArgumentException` unless `ReplaceExisting` is set. Removing or extracting a name that doesn't exist throws `PdfAttachmentNotFoundException`.
* `ExtractAttachmentAsync` also finds file attachment annotations, and returns the decoded bytes (FlateDecode).
* PDF/A-1 and PDF/A-2 input gets a warning, as does PDF/A-3 input without a `Relationship`. Output below PDF 1.3 is raised to 1.3, where embedded files were introduced.
* Protected files keep exactly the same security (adding or removing needs the owner password; extracting works with either password).

### Smaller files and incremental saves

**Compressed output.** Every operation that writes a PDF takes `Write = new PdfWriteOptions { UseObjectStreams = true }`. Objects are then packed into compressed object streams and the cross-reference table becomes a cross-reference stream, which needs PDF 1.5, so the version is raised to at least 1.5.

```csharp
var small = Pdf.Protect("book.pdf", "book-small.pdf", new PdfProtectionOptions
{
    UserPassword = "open-sesame",
    Write = new PdfWriteOptions { UseObjectStreams = true },
});
// A 200-page test file: 99,707 bytes with the default layout, 30,820 bytes compressed.
```

The encryption rules of ISO 32000 §7.6 apply: an object stream is encrypted as a whole (the objects inside are not encrypted one by one), the cross-reference stream is never encrypted, and signature dictionaries and the encryption dictionary are never packed. Readers older than about 2003 (Acrobat 5) can't open such files, so the default stays the most compatible layout.

**Incremental saves.** `EditInfo`, `AddAttachment` and `RemoveAttachment` take `SaveMode = PdfSaveMode.Incremental`. The original bytes are then kept exactly and the change is appended as an update: a cross-reference section in the same style as the source (table or stream), `/Prev` pointing at the previous one, the same `/ID[0]` and a new `/ID[1]`.

```csharp
var result = Pdf.EditInfo("report.pdf", "report-edited.pdf", new PdfEditInfoOptions
{
    Changes = new PdfInfoChanges { Title = "Q3 report (final)" },
    SaveMode = PdfSaveMode.Incremental,
});
// result.SaveMode == Incremental; report-edited.pdf starts with report.pdf byte for byte.
```

* Self-verification checks that the original bytes are unchanged, that every appended object reads back as planned, and that every other object still comes from the original revision.
* Signed documents keep their signed bytes intact, so the signatures stay valid for what they cover (viewers will show the document was changed after signing).
* Only unencrypted documents with a readable cross-reference chain are supported; anything else throws `NotSupportedException`. Incremental mode can't be combined with `UseObjectStreams`.
* Anything replaced or removed stays in the earlier revision. Removing an attachment incrementally adds a warning, and sanitizing is always a full rewrite.
* A required version increase (for example to 1.3 for attachments) goes into the catalog `/Version`, because the header is part of the original bytes.

### Page operations

`IPdfPageEditor` (or the `Pdf` facade) rotates, deletes, merges and splits pages. Pages are selected with one shared syntax, `PdfPageRange.Parse("1-3, 5, 8-")`: single pages, ranges, open ranges (`8-`, `-4`), and `odd`, `even` and `last`.

```csharp
var rotated = Pdf.RotatePages("book.pdf", "book-rotated.pdf", new PdfRotatePagesOptions
{
    Angle = 90,
    Pages = PdfPageRange.Parse("1-3, 10"),
});
var trimmed = Pdf.DeletePages("report.pdf", "report-trimmed.pdf", new PdfDeletePagesOptions { Pages = PdfPageRange.Parse("2") });
Console.WriteLine($"Rotated: {rotated.PageCount} pages; trimmed: {trimmed.PageCount} page(s)");
foreach (var line in trimmed.Removed)
    Console.WriteLine(line);
```

* **Rotate** adds a multiple of 90° to each page's current rotation, including rotation inherited from the page tree.
* **Delete** writes a flat page tree with inherited attributes resolved onto each page, and removes, with a report line each, links, bookmark destinations, named destinations, the open action and form fields that pointed at deleted pages. Page labels are renumbered. Deleting every page throws `ArgumentException`.
* Both keep protection exactly as it is (the owner password is needed for protected files).

```csharp
var merged = Pdf.Merge(new[]
{
    PdfMergeInput.FromFile("report.pdf"),
    PdfMergeInput.FromFile("book.pdf", pages: PdfPageRange.Parse("1-5")),
}, "combined.pdf", new PdfMergeOptions { Outlines = PdfMergeOutlineMode.PerDocument });
Console.WriteLine($"Merged: {merged.PageCount} pages from {string.Join(" + ", merged.PagesPerInput)}");
foreach (var bookmark in Pdf.Inspect("combined.pdf").Bookmarks)
    Console.WriteLine($"  {bookmark.Title} -> page {bookmark.Page}");

var split = Pdf.Split("book.pdf", "book-part-{0}.pdf", new PdfSplitOptions { EveryNPages = 50 });
```

* **Merge** copies pages with their inherited attributes resolved, and combines bookmarks (one entry per document, flat, or none), named destinations and form fields (renamed on conflict, reported in `Renamed`), the form's default resources and `NeedAppearances`, and attachments. `DeduplicateResources` stores identical fonts and images once. The output takes the highest input version.
* **Split** writes one part per range, or parts of `EveryNPages`. Each part contains only the objects its pages need; links to pages in other parts are removed and reported.
* Protected inputs need their owner password (or the password to open them, with `AllowUserPassword`). The output is unencrypted unless `Protection` is set.
* Not kept by merge and split (each with a warning): tags (logical structure), page labels, document JavaScript, XFA, XMP.
* Every composed document is verified: every object round-trips, and every page has the source page's geometry and exact content bytes.

### Text extraction

`Pdf.ExtractText` (or `IPdfTextExtractor.ExtractAsync`) returns each page's text and a positioned model: text runs (font, size, bold, italic, colour, baseline, bounds, angle, and optionally each glyph) and image placements. Coordinates are in points in display space: the page as a viewer shows it (crop box and rotation applied), origin at the bottom-left.

```csharp
var result = Pdf.ExtractText("report.pdf");
Console.WriteLine(result.Text);
foreach (var run in result.Pages[0].Runs)
    Console.WriteLine($"\"{run.Text}\" {run.FontName} {run.FontSize}pt at ({run.X}, {run.Y}) {run.Color}");
```

* Fonts are decoded through `/ToUnicode` maps (bfchar, bfrange, multi-byte codes), the standard, WinAnsi, MacRoman, PDFDoc and Symbol encodings with `/Differences` and glyph names, Type 3 fonts, and Type0 fonts with Identity or Unicode-based CMaps (UniGB-UCS2-H, UniJIS-UTF16-H, ...).
* Form XObjects and inline images are followed; content streams compressed with Flate, LZW, ASCIIHex, ASCII85 or RunLength are read.
* `Order = PdfTextOrder.Content` (default) keeps the order the document draws text in; `Layout` sorts lines by position.
* Protected documents need a password that opens them; if the owner forbids copying, a warning says so.

Limits:

* No OCR: text that is part of an image, or drawn as vector shapes, is not found.
* Fonts without a `/ToUnicode` map that use Identity-H (common in CJK documents) or glyph names without a standard meaning give U+FFFD; `UnknownGlyphCount` says how many.
* Spaces and line breaks are inferred from positions, so they can differ from what a viewer's copy-and-paste gives.
* Vertical text is read as horizontal text. Layout order reads multi-column pages across, line by line; content order usually follows the columns.
* Widths of standard fonts are exact for ASCII; other characters use their base letter's width.

### Watermarks and stamps

`Pdf.Stamp` (or `IPdfStamper.StampAsync`) adds text or an image to pages, over or under the content.

```csharp
var result = Pdf.Stamp("report.pdf", "report-confidential.pdf", new PdfStampOptions
{
    Text = "CONFIDENTIAL",
    FontSize = 60,
    Color = PdfColor.FromHex("#C00000"),
    Opacity = 0.25,
    Rotation = 45,
});
Console.WriteLine($"Stamped pages: {string.Join(", ", result.StampedPages)}");

Pdf.Stamp("report.pdf", "report-logo.pdf", new PdfStampOptions
{
    Image = File.ReadAllBytes("logo.png"),
    ImageWidth = 72,                       // one inch wide
    Position = PdfStampPosition.TopRight,
    Rotation = 0,
    Opacity = 1,
    Pages = PdfPageRange.Parse("1"),
});
```

* Text uses a standard 14 font (no embedding) and must be WinAnsi (Windows-1252) text; anything else is rejected with the characters listed. `\n` starts a new line.
* Images: JPEG is passed through unchanged; non-interlaced PNG is decoded, and its transparency becomes a soft mask.
* Positions are presets (centre, corners, edges, with `Margin`) or custom coordinates, on the page as displayed: rotated pages and crop boxes are respected. `Rotation` turns the stamp around its centre; `Opacity` uses an ExtGState.
* Existing content streams are never re-encoded: the stamp is a new content stream, and "over" wraps the existing content in `q … Q`.

### Digital signatures and certificate encryption (PdfUtil.Signatures)

The `PdfUtil.Signatures` package adds signing, signature verification and certificate encryption. It depends on `System.Security.Cryptography.Pkcs` (Microsoft); register it with `services.AddPdfUtilSignatures()`.

```csharp
IPdfSigner signer = new PdfSigner();
await signer.SignFileAsync("report.pdf", "report-signed.pdf", new PdfSignOptions
{
    Certificate = new X509Certificate2("signer.pfx", pfxPassword),
    Reason = "Approved",
    Appearance = new PdfSignatureAppearance { Page = 1, Bounds = new PdfRectangle(36, 36, 236, 96) },
});

await using var signed = File.OpenRead("report-signed.pdf");
var verification = await signer.VerifyAsync(signed);
foreach (var signature in verification.Signatures)
    Console.WriteLine($"{signature.FieldName}: {(signature.IsValid ? "valid" : "INVALID")}, signed by {signature.SignerName}, {signature.SubFilter}, covers whole file: {signature.CoversWholeFile}");
```

* **Signing** writes a PAdES baseline B-B signature (`ETSI.CAdES.detached`, SHA-256/384/512, RSA or ECDSA, with the ESS signing-certificate-v2 attribute), invisible or visible, in a new field or an existing unsigned one. `TimestampServer` adds an RFC 3161 timestamp (B-T); the `HttpClient` is injectable. The signature is always appended as an incremental update, so earlier signatures stay valid, and the result is verified before it is returned. Only unencrypted documents can be signed. A key that isn't attached to the certificate (for example from a hardware module) goes in `PrivateKey`.
* **Verification** checks the byte-range digest and the CMS signature (`adbe.pkcs7.detached`, `ETSI.CAdES.detached`, `adbe.pkcs7.sha1`, and `ETSI.RFC3161` document timestamps), reports the signer, digest algorithm, signing and timestamp times, the revision signed, whether later revisions changed the document and what kind of changes they made, and, with a `ChainPolicy`, the certificate chain.

```csharp
IPdfCertificateSecurity security = new PdfCertificateSecurity();
await security.ProtectFileAsync("report.pdf", "report-for-alice.pdf", new PdfCertificateProtectionOptions
{
    Recipients = new[] { new PdfCertificateRecipient(aliceCertificate, PdfPermissions.All) },
});
Console.WriteLine($"Needs a certificate: {Pdf.GetInfo("report-for-alice.pdf").RequiresCertificate}");

await security.DecryptFileAsync("report-for-alice.pdf", "report-open.pdf", new PdfCertificateDecryptOptions
{
    Certificate = aliceCertificate,
    PrivateKey = aliceKey,                 // or a certificate with its private key attached
});
Console.WriteLine($"Encrypted after decrypting: {Pdf.IsEncrypted("report-open.pdf")}");
```

* **Certificate encryption** writes `/Adobe.PubSec` with `adbe.pkcs7.s5` (AES-256 or AES-128 crypt filters): each recipient gets the key in a CMS envelope for their certificate, with their own permissions. Decrypting needs a recipient's private key, and by default a recipient with every permission.
* Without the package, `GetInfo` and `VerifyPassword` report certificate-encrypted documents (`RequiresCertificate`, the recipient count) instead of throwing.
* Certificate-encrypted files open in Adobe Acrobat and Reader; browsers (pdf.js, PDFium) and Apple Preview don't support them.

### Converting PDF to HTML (PdfUtil.Conversion)

The `PdfUtil.Conversion` package converts PDFs to HTML. It depends only on the core package and the .NET base class library; register it with `services.AddPdfUtilConversion()`.

```csharp
IPdfConverter converter = new PdfConverter();
var result = await converter.ConvertToHtmlFileAsync("article.pdf", "article.html", new PdfToHtmlOptions
{
    Layout = PdfHtmlLayout.Reflow,              // or Fixed: one positioned box per page
    Images = PdfHtmlImageMode.SeparateFiles,    // article_files/image-1.png, ...
});
Console.WriteLine($"{result.PageCount} page, {result.HeadingCount} headings, {result.ListCount} list, {result.ImageCount} image, {result.LinkCount} link");
Console.WriteLine(string.Join(", ", result.AssetFiles));
```

```
1 page, 2 headings, 1 list, 1 image, 1 link
article_files/image-1.png
```

* **Reflow** layout rebuilds paragraphs, headings, lists and reading order, for reading on any screen. **Fixed** layout keeps every page as it looks, with text runs and images at their positions.
* Images go inside the file as data URIs (default), as separate files in a folder next to it (`SeparateFiles`, file output only), or are left out.
* The output is HTML5 that is also well-formed XML (`Xhtml = true` adds an XML declaration). Before it is returned, it is checked: well-formed, unique ids, every internal link resolves, every image exists, and no scripts or unsafe links. Conversion never fetches anything from the network.
* `PdfConversionLimits` caps image size (pixels) and the number of output elements.

What is supported:

| Area | Support |
|---|---|
| Text | Every font encoding text extraction supports (F15); fonts as CSS families with serif, sans-serif or monospace fallback; size, bold, italic, colour |
| Reflow structure | Paragraphs (from line spacing, indentation and sentence ends, joined across page breaks), headings h1–h6 (one level per larger size, plus short bold lines), bulleted and numbered lists (decimal, letters, roman; nested by indentation), superscript and subscript, underline and strike-through drawn as lines, monospace blocks as `pre` |
| Reading order | Columns read one after the other when a clear gutter separates them (recursive XY cut) |
| Fixed layout | One box per page with the page's displayed size (rotation applied); text runs, images and link areas positioned in points; invisible text (OCR layers) kept selectable but transparent |
| Links | Web, mail and phone links (http, https, mailto, ftp, tel) and links to pages of the document; other actions are dropped with a warning |
| Bookmarks, metadata | Bookmarks become a navigation list; Title, Author, Subject, Keywords and `/Lang` go into the head |
| Images | JPEG passed through; Flate, LZW, RunLength and ASCII images in Gray, RGB, CMYK, Cal, ICC-based, Indexed (and Separation, as gray) converted to PNG, with soft masks, stencil masks and colour-key masks as transparency; JPX, JBIG2 and CCITT become placeholders |

Known limitations:

* No OCR: text drawn as images or vector paths is not found.
* Vector graphics (lines, shapes, fills) are not converted, apart from underlines; tables come out as paragraphs (table detection arrives with PDF to Word).
* Embedded fonts are not extracted as web fonts; the browser uses a font of the same name if installed, or the generic family, so fixed-layout text can be slightly wider or narrower than in the PDF.
* Structure is reconstructed from the layout; tagged-PDF structure trees are not read yet.
* Vertical writing is laid out horizontally; right-to-left text keeps its stored order.

## Password encoding rules

One internal `PasswordEncoder` is used for both protection and verification. Passwords are never trimmed or case-folded, and the empty user password is supported (the document opens without a password and permissions apply). If no owner password is given, a random one is generated and discarded.

| | AES-256 (R6) | RC4-128 / AES-128 (R3/R4) |
|---|---|---|
| Specification rule | SASLprep (RFC 4013), then UTF-8, truncated to 127 bytes | PDFDocEncoding, padded or truncated to 32 bytes |
| Longer passwords | Truncated to 127 bytes consistently in protection and verification | Rejected, unless `AllowPasswordTruncation = true` |
| Accepted by the default `PasswordPolicy.Interoperable` | Basic Multilingual Plane text that SASLprep leaves unchanged and that has no canonical decomposition: Latin ASCII, Cyrillic, Greek, CJK ideographs, Arabic, Hebrew | Printable ASCII |
| Additionally accepted by `PasswordPolicy.Specification` | Accented Latin letters, Hangul, emoji, non-ASCII spaces (all SASLprep-valid input) | All of PDFDocEncoding |
| Always rejected, with a clear error | SASLprep-prohibited characters (controls, private use, non-characters) and invalid bidirectional text | Characters outside PDFDocEncoding |

**Why the default is stricter than the specification.** The rule is that *a correct password must never become invalid* in any viewer. Automated interop tests against real readers showed that readers disagree outside these sets:

* **Legacy passwords.** pdf.js uses the low byte of each code point. Apple PDFKit (Safari, Preview, iOS) uses UTF-8. Acrobat has historically used the platform code page. Only printable ASCII is encoded identically by all of them.
* **AES-256 passwords.** pdf.js uses the plain UTF-8 of the typed text, without SASLprep. PDFKit decomposes accented letters and mishandles characters outside the BMP, such as emoji. These readers only agree when SASLprep changes nothing and the text is decomposition-free BMP text.

Errors never contain the password. When verifying third-party files, PdfUtil also tries the encodings other producers use: ISO 8859-1 and UTF-8 for legacy files, and plain UTF-8 without SASLprep for AES-256 files.

SASLprep notes: tables B.1, C.1.2–C.9 and D.1 of RFC 3454 are embedded literally. The D.2 (left-to-right) classification is derived from the BCL's Unicode general categories, and NFKC uses `string.Normalize`. Unassigned code points are allowed ("query" semantics), so characters added to Unicode after version 3.2 are accepted under `Specification`.

## Trailer `/ID` guarantees

* `/ID` is handled as two **byte arrays**. It never passes through any text decoder. Leading `FE FF` or `EF BB BF`, `00`, `\`, `(`, `)` and CR/LF are kept exactly, and IDs of any length are neither truncated nor padded.
* `/ID[0]` (the permanent ID) is **preserved byte-for-byte**. If it is missing or malformed, 16 random bytes are generated.
* `/ID[0]` is fixed **before** key derivation. The same bytes feed Algorithm 2 (R2–R4) and are written to the output, and self-verification checks that they match.
* `/ID[1]` (the changing ID) is regenerated on every save and never used in key derivation.
* For incremental updates, the ID from the **last** trailer or xref stream is used. The output has exactly one trailer containing `/ID` and `/Encrypt`.
* Both entries are written as hex strings and are never encrypted.
* `PdfDocumentInfo.PermanentId` / `ChangingId` (`byte[]`) and `PermanentIdHex` / `ChangingIdHex` expose them.

## Text strings (metadata)

PDFDocEncoding, UTF-16BE with `FE FF`, and UTF-8 with `EF BB BF` (PDF 2.0) are all decoded, including surrogate pairs. Language escape sequences (`ESC lang ESC`) are stripped. Strings are decrypted first and decoded afterwards, because the BOM is part of the encrypted bytes. On output, string bytes are encrypted as-is, so the BOM is included and nothing is double-encoded. UTF-8 Info strings are converted to UTF-16BE when the output version is below 2.0.

## Mandatory self-verification

After writing, PdfUtil re-parses the output with its own reader in strict mode, with no repair allowed. It checks that:

* the header version is right;
* there is a single classic xref table and every xref offset is exact;
* `/Size` is correct;
* `/ID[0]` equals the key-derivation bytes;
* the `/Encrypt` dictionary is exactly as specified;
* a wrong password fails, the user password authenticates as User and the owner password as Owner, through both the exact bytes and the public string path;
* `/Perms` validates (R6);
* every object decrypts (with strict AES padding) to exactly the intended object;
* every stream's decrypted bytes equal the source bytes, and FlateDecode streams still inflate;
* page count, page geometry, the Info dictionary and the XMP packet match the source.

Any failure throws `PdfVerificationException`, and no output is produced.

## Errors

| Exception | Meaning |
|---|---|
| `PdfUtilException` | Base class |
| `PdfInvalidPasswordException` | A wrong password was given (to `GetInfoAsync`, `ValidateAsync`, as an owner password, ...); `VerifyPasswordAsync` returns a result instead of throwing |
| `PdfCorruptException` / `PdfLimitExceededException` | Not a PDF, damaged beyond repair, or a hostile-input limit was hit |
| `PdfUnsupportedEncryptionException` | Public-key or unknown security handler |
| `PdfAlreadyEncryptedException` | Encrypted input with `AlreadyEncryptedPolicy.Throw` |
| `PdfNotEncryptedException` | `ChangeSecurityAsync` on an unprotected document |
| `PdfComplianceException` | PDF/A input with `PdfAPolicy.Throw` |
| `PdfPasswordEncodingException` | The password cannot be encoded safely for the chosen algorithm and policy |
| `PdfAttachmentNotFoundException` | No attachment with the requested name |
| `PdfVerificationException` | The output failed self-verification (no output was written) |

Invalid options throw `ArgumentException`. An incremental save of an encrypted or damaged document throws `NotSupportedException`.

## Production notes

* **Thread safety.** The services are stateless and safe to use as singletons, and options are copied at construction.
* **Async.** Input buffering and output copying are asynchronous and cancellable. Parsing and encryption are CPU-bound synchronous code that checks the token regularly.
* **Large files.** The reader uses a windowed, `ArrayPool`-backed source over a seekable stream, and stream data is read on demand. Non-seekable input is buffered in memory up to `InMemoryBufferThresholdBytes` and in a temporary file beyond that.
* **Hostile input.** `MaxFileSizeBytes`, `MaxObjectCount`, `MaxNestingDepth`, `MaxDecompressedStreamBytes` (zip-bomb protection) and `MaxXrefSections` are configurable, and `/Prev` loops and page-tree cycles are detected. Unexpected failures inside the parser are reported as `PdfCorruptException`.
* **Secrets.** Passwords are never logged, cached or included in messages or `ToString()`. Password and key buffers are cleared with `CryptographicOperations.ZeroMemory`, and hash comparisons use `CryptographicOperations.FixedTimeEquals`.

## Tests

```bash
dotnet test
```

The suite includes:

* known-answer tests for RC4, Algorithms 1–7, 2.A, 2.B, 8–10, R5 and AES (vectors from an independent implementation);
* the version matrix (1.0–2.0 × every algorithm);
* the structure matrix (classic, xref streams, object streams, hybrid, linearized, incremental, broken xref, wrong `/Length`, junk before the header, 19/21-byte entries, predictors) × every algorithm;
* `/ID` edge cases;
* metadata encodings;
* password rules;
* PDF/A and signatures;
* content preservation;
* failure paths;
* 1,000 randomized protections;
* inspection of fonts, images, attachments, bookmarks, form fields, signatures, page labels and actions on every structure and revision;
* validation of every kind of damage the builder can produce, repair of each, sanitizing and attachments, including hostile cycles in outlines, name trees, field trees and action chains.

**Optional interop tests** run each reader as an external process over a corpus covering every version and structure × every algorithm, and are skipped when the tool is absent:

* `qpdf --check --password=…` and `mutool info -p …`, when installed;
* **pdf.js**: run `npm install pdfjs-dist` in a directory and set `PDFUTIL_PDFJS_DIR` to it;
* **Apple PDFKit** (Safari, Preview, iOS engine): runs automatically on macOS through `swift`.

See `docs/manual-compat-checklist.md` for the viewers that must be checked by hand. `dotnet run --project samples/PdfUtil.Sample -- demo ./out` creates the sample files for that checklist.
